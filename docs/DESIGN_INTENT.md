# 제작 의도

## 왜 이렇게 설계했는가

### 1. 3칸 대시보드 구조

대시보드를 영상 탐색 → 분석/초안 → 실행의 3단계 파이프라인으로 설계했습니다.
각 단계가 독립적으로 동작하면서도 자연스럽게 연결되어, 처음 보는 사람도
왼쪽에서 오른쪽으로 따라가면 됩니다.

### 2. AI 댓글 생성 전략

단순히 "운명원 광고 댓글"을 만드는 것이 아니라, 영상 내용을 깊이 분석하는 구조입니다:

1. **자막 분석**: 영상에서 실제로 언급된 구체적 장면/대사를 추출
2. **시청자 페르소나**: "이 영상을 보고 공감한 시청자"의 입장에서 작성
3. **자연스러운 전환**: 공감 → 개인 경험 → 운명/사주에 대한 호기심으로 이어지는 흐름

이렇게 하면 스팸이 아닌, 실제 시청자의 댓글처럼 읽힙니다.

### 3. Playwright + 크롬 프로필

YouTube API의 댓글 작성 기능(insert) 대신 Playwright 브라우저 자동화를 선택한 이유:

- **API 방식의 한계**: YouTube Data API로 댓글을 달면 봇으로 감지될 확률이 높음
- **사람처럼 행동**: 한 글자씩 타이핑, 자연스러운 딜레이로 사람의 행동 패턴 모방
- **기존 계정 활용**: `launchPersistentContext`로 이미 로그인된 크롬 프로필을 그대로 사용
- **시각적 확인**: 실제 브라우저에서 댓글이 달리는 과정을 눈으로 확인 가능

### 4. 운영 규칙을 코드로 강제

"영상당 1개, 하루 10개"를 사용자의 자제에 맡기지 않고 DB에서 체크합니다:

- 댓글 시도 전 DB에서 해당 영상 + 오늘 게시 수 조회
- 규칙 위반 시 버튼 비활성화 + 사유 안내
- 모든 게시 기록을 시간순으로 저장하여 투명하게 관리

### 5. 기술 스택 선택 근거

| 기술 | 선택 이유 |
|------|----------|
| Python + Streamlit | 단일 파일로 대시보드 구현, 빠른 개발, `streamlit run` 한 줄 실행 |
| Playwright (Python) | Puppeteer 대비 안정적인 persistent context 지원, Python 생태계 통합 |
| Claude API | 한국어 맥락 이해와 자연스러운 댓글 생성에 강점 |
| youtube-transcript-api | YouTube 자막을 직접 추출하여 영상 내용 깊이 분석 |
| SQLite | 별도 DB 서버 없이 로컬 파일 하나로 기록 관리 |

### 6. 확장 가능성

현재 구조는 운명원 마케팅에 최적화되어 있지만, 설정만 바꾸면 다른 브랜드·다른 플랫폼에도 적용 가능합니다:

- `brand` 설정 변경으로 타겟 브랜드 교체
- 검색 키워드 변경으로 다른 카테고리 영상 타겟
- Playwright 스크립트 수정으로 인스타그램, 네이버 블로그 등 확장
